# 3트랙 운영 규약 (2026-08-17)

사용자 요청: "과장(메인 에이전트)이 하위 에이전트에게 지시하고 나에게 보고하는 구조".
Paperclip과 같은 방식을 orca orchestration으로 구현한다.

## 구조

```
사용자
  ↕            ← 요청·보고는 항상 이 한 경로로만
과장 (메인 세션)          Run: run_0c845781dc0c
  ├─ A 출력 품질   task_635f0b145a01   (과장이 직접)
  ├─ B 디자인·조작감 task_b8d5063afcba  (워커 디스패치)
  └─ C 출시 준비    task_a2eedf3e2927  (워커 디스패치)
```

**하위 에이전트는 사용자와 직접 말하지 않는다.** 결과는 과장에게 오고, 과장이 정리해
사용자에게 보고한다. 사용자는 어느 트랙인지 몰라도 되고, 분류는 과장이 한다.

## 트랙 경계 — "결과물이 바뀌는가"로 가른다

| 트랙 | 범위 | 워크트리 |
|---|---|---|
| **A 출력 품질** | STT·VAD·화자분리·구두점·자막 분할 — FCPXML 결과가 달라지는 모든 것 | `.git-src/figma-design-system` + 엔진 레포 |
| **B 디자인·조작감** | 버튼 위치·크기·색·간격·단축키·애니메이션 — 결과물 불변 | `.git-src/track-b-design` |
| **C 출시 준비** | MAS/웹 빌드 분리, 라이선스·트라이얼, 서명·공증, 릴리스 체크리스트 | `.git-src/track-c-release` |

### UI/엔진으로 가르지 않는 이유 (실측 근거)

2026-08-16~17에 겪은 두 사건이 그 경계가 틀렸음을 보여준다.

- **"진행바가 안 뜬다"** — 증상은 UI, 원인은 **엔진 출력(분석 캐시)에 UI 상태가 묶인 것**.
- **"가짜 스피커 2가 생긴다"** — 증상은 UI, 원인은 **엔진의 `min_speakers=2` 하한**.

증상으로 트랙을 정했다면 양쪽 담당자 모두 자기 층에서 원인을 못 찾았을 것이다.
그래서 **진단은 과장이 하고, 하위 에이전트에게는 원인이 특정된 뒤 구현만 맡긴다.**

## 운영 규칙

1. **A는 과장이 직접 한다.** 측정(정답표)이 얽혀 있어 병렬로 쪼개면 실험이 뒤엉킨다.
2. **B·C는 워커에게 맡긴다.** 단, 스펙이 확정된 뒤에만. 진단이 필요한 일은 A로 간다.
3. **경계가 애매하면 과장이 먼저 사용자에게 확인한다.** 임의로 분류하지 않는다.
4. **병합 충돌 관리** — B가 `PreparePane.swift`처럼 A도 만지는 파일을 건드려야 하면
   그 작업은 A로 옮긴다. B는 결과물이 안 바뀌는 겉모습에 한정한다.
5. **워커 시작은 비용이 든다.** 상시 대기시키지 않고, 스펙이 준비된 시점에만 띄운다.

## 명령 (과장용)

```bash
orca orchestration task-list --json                     # 현황
orca orchestration worker-start --task <id> \           # 워커 투입
  --worktree path:/Users/chrictvictory/코딩/.git-src/track-b-design --agent claude
orca orchestration worker-read --dispatch <id>          # 중간 산출물 확인
orca orchestration task-update --task <id> --status done
```

병합은 **디시전 게이트** — 사용자 승인 전까지 main에 넣지 않는다(CLAUDE.md 규약).
