# 대본 편집기의 세 가지 조작 — 무엇이 섞여 있고 어떻게 갈라야 하나 (2026-08-19)

사용자 문제 제기:

> 실제 문장을 지워버리는 것(영상편집) / 자막을 분리하는 것(자막 분리) /
> 실제 자막의 수정 및 삭제(자막 수정 및 삭제) 의 로직이 달라야 할 것 같다.

맞는 지적이다. **지금은 축이 둘인데 조작이 한 축처럼 다뤄지는 곳이 있다.**
아래는 코드를 읽어 확인한 현재 상태와, 갈라야 할 지점이다.

## 2. 축은 둘이다

- **타임라인 축** — 영상에서 그 구간을 잘라낼 것인가
- **자막 축** — 자막에 그 말을 띄울 것인가 / 어디서 끊을 것인가 / 뭐라고 적을 것인가

두 축은 **독립**이다. 그런데 표를 보면 조합 네 칸 중 하나가 비어 있다.

| | **영상 유지** | **영상 컷** |
|---|---|---|
| **자막 유지** | (조작 없음 = 기본) | `gapCuts` — **무음 구간에만** |
| **자막 제거** | **❌ 수단이 없다** | `deleted` |

`deleted` 하나가 **두 축을 동시에** 움직인다. 그래서 "이 말은 영상에 남기되
자막에는 안 띄우고 싶다"를 표현할 방법이 없다.

### 그 칸이 왜 필요한가 (실제 상황)

- 군소리 "어·음·그" — 말맛이라 영상에선 남기고 싶은데 자막에 뜨면 지저분하다
- 웃음·감탄사·추임새
- 화면에 이미 큰 자막 그래픽이 있는 구간
- 노래·구호처럼 자막이 방해되는 구간
- 겹쳐 말한 상대 화자의 맞장구

지금은 이걸 하려면 **영상까지 잘라야 한다.** 그래서 사용자는 둘 중 하나를 포기한다.

> 반대 칸(영상은 자르고 자막은 남김)은 비워 두는 게 맞다 — 소리가 없는데 자막만
> 뜨는 것은 의미가 없다. `gapCuts`가 무음에만 열려 있는 것도 같은 이유다.

## 3. 가장 위험한 곳 — 글자를 지우다 영상이 잘린다

`TranscriptTextView.swift:428-432`:

```swift
if replacement.isEmpty {
    // 단어의 모든 글자를 지우는가 — 빈 단어를 만들지 않고 삭제 표시로 전환
    let wholeWord = ownerAt(range.location - 1) != w
        && ownerAt(range.location + range.length) != w
    return wholeWord ? .deleteWord(w) : .edit(w)
}
```

**글자를 하나씩 지우다 마지막 글자를 지우는 순간 `.edit`이 `.deleteWord`로 바뀐다.**
사용자는 오타를 고치려고 글자를 지웠을 뿐인데 그 단어 구간이 **영상에서 잘린다.**

같은 `⌫` 한 키가 캐럿 위치에 따라 다섯 가지로 갈린다:

| 캐럿 위치 | 하는 일 | 축 |
|---|---|---|
| 범위 선택 | 단어 삭제 | **타임라인** |
| 자막 첫 글자 | 앞 자막과 병합 | 자막 |
| 조각 경계 | 쪼갠 것 되돌리기 | 자막 |
| 단어 사이 공백 | 두 단어 붙이기 | 자막 |
| 단어 마지막 글자 | **단어 삭제** | **타임라인** |
| 그 밖 | 글자 삭제 | 자막 |

한 키가 두 축을 오간다. **되돌리기 비용이 전혀 다른 동작인데 같은 키다.**

## 4. 정리 — 이렇게 갈라야 한다

### 4.1 조작을 축으로 이름 붙인다

| 이름 | 뜻 | 축 | 제안 키 |
|---|---|---|---|
| **컷** | 이 구간을 영상에서 잘라낸다 | 타임라인 | `⌘⌫` (또는 선택 후 우클릭) |
| **자막에서 빼기** | 영상은 두고 자막에만 안 띄운다 | 자막 | `⌥⌫` |
| **자막 나누기 / 합치기** | 자막 경계 | 자막 | `⏎` / 자막 첫 글자 `⌫` |
| **글자 고치기** | 자막 텍스트 | 자막 | 그냥 타이핑 |

핵심: **타임라인을 건드리는 조작에는 수식키를 요구한다.** 맨 `⌫`는 자막 축에서만
논다. 지금처럼 마지막 글자를 지웠다고 영상이 잘리는 일이 없어진다.

### 4.2 상태를 하나 더 만든다

```
deleted      — 영상 컷 + 자막 제거 (지금 그대로, 이름만 "cut"으로)
mutedCaption — 영상 유지 + 자막에서만 제외          ← 신설
gapCuts      — 무음 컷 (지금 그대로)
edits        — 텍스트 수정 (지금 그대로)
breaksAdd/Del — 자막 경계 (지금 그대로)
```

엔진 계약은 `caption_mute[]`를 추가한다. 처리 위치는 `deleted`와 다르다:

- `deleted` → 단어를 런에서 빼고 `cut_ranges`에 넣는다 (`engine.py:581-592`)
- `caption_mute` → **런에는 남기고** 자막 청크를 만들 때만 뺀다
  (`words_to_analysis` 직전). 타임코드·컷은 손대지 않는다.

이게 중요한 이유: 런에서 빼 버리면 앞뒤 단어가 붙어 **자막 경계가 달라지고**
화자 런도 흔들린다. 자막 축 조작이 타임라인 축에 새면 안 된다.

### 4.3 화면에서도 갈라 보인다

지금은 삭제가 취소선 하나다. 두 가지를 눈으로 구분해야 한다.

- **컷** — 취소선 + 흐리게 (지금 그대로). "이건 영상에서 사라진다"
- **자막에서 빼기** — 글자는 살아 있고 **회색 점선 밑줄**. "들리지만 안 뜬다"

푸터 표기도 축을 갈라야 한다. 지금은 `단어 N · 삭제 N · 무음컷 N · 수정 N`인데
`삭제`가 어느 축인지 안 보인다:

```
영상  컷 N · 무음 N
자막  숨김 N · 수정 N · 경계 N
```

### 4.4 되돌리기·확인 강도도 다르다

| 조작 | 파괴력 | 지금 | 제안 |
|---|---|---|---|
| 글자 수정 | 낮음 (텍스트만) | 0.5초 병합 스냅샷 | 그대로 |
| 자막 경계·숨김 | 낮음 (되돌리기 쉬움) | 매번 스냅샷 | 그대로 |
| 컷 | **높음 (영상이 잘린다)** | 매번 스냅샷 | **여러 문장 한꺼번에 자를 땐 확인** |

지금 AI 대량 삭제만 승인 시트(`bulkDeletePlan`)를 거친다. 사람이 여러 문장을
선택해 자르는 것도 같은 무게다.

## 6. 결정이 필요한 것

1. **빈 단어를 허용할 것인가.** 마지막 글자를 지웠을 때 컷으로 넘기지 않으려면,
   빈 단어를 잠깐 허용하거나(다음 입력을 기다린다) 이전 글자를 되살려야 한다.
   원문 불변 원칙과 부딪히는 지점이라 여기 결정이 나머지를 좌우한다.
2. **`⌫` 과부하를 어디까지 풀 것인가.** 다섯 갈래 중 자막 축 넷은 남겨도 되지만,
   타임라인 축 둘(범위 삭제·단어 삭제)은 수식키로 옮기는 것이 이 정리의 핵심이다.
3. **기존 프로젝트 호환.** 저장된 `deleted`는 그대로 컷으로 읽는다(의미 변화 없음).
   새 키만 추가하면 되므로 마이그레이션은 필요 없다.

## 부록 — 확인하지 않은 것

- 이 문서는 **코드를 읽어** 정리한 것이고, 사용자가 실제로 어떤 비율로 "자막만
  빼고 싶다"를 원하는지는 **측정하지 않았다.** 4.2의 신설 상태가 얼마나 쓰일지는
  근거가 없다.
- `⌫` 다섯 갈래가 실제 사용에서 얼마나 헷갈리는지도 관찰 기록이 없다. 3절의
  "마지막 글자 삭제 → 영상 컷"만은 코드로 확정된 사실이다.
