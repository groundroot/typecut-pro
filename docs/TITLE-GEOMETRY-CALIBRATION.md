# 자막 위치·크기 캘리브레이션 실측 (2026-08-17)

**측정 방법**: `tools/title_probe.py`(엔진 레포) + SpliceKit으로 FCP 뷰어 직접 캡처.
프레임 높이 10%마다 **마젠타 기준선**이 있는 배경 위에 엔진의 실제 함수
(`_add_subtitle_elements`)로 타이틀을 얹고, 캡처에서 마젠타 경계 상자를 프레임으로
삼아 자막의 y중심·글자 높이를 **프레임 높이 대비 비율**로 읽었다.

측정 환경: FCP 12.3 (build 450152), macOS 26.5.2, SpliceKit 3.3.9,
템플릿 `Custom.moti` (title_style=custom123 = 앱 기본 경로), Helvetica, font 100.

> 이 문서는 **측정값**만 담는다. 추정은 담지 않는다. 이슈 #3("Y 캘리브레이션,
> FCP 실측 대기")이 실측 없이 닫히지 못했던 항목이다.

---

## 1. 핵심 실측 — conform 배수만큼 위치가 뻥튀김했다

같은 글자(`Xygq`), 같은 폰트(100), 같은 요청 `y_frac = -0.15`:

| 프로젝트 | conform | 엔진이 쓴 Position | **측정 렌더 위치** | 측정 글자 높이 |
|---|---:|---:|---:|---:|
| 1920×1080 | 1.0 | `0 -162` | **−0.1287** | 0.0858 |
| 3840×2160 (수정 전) | 2.0 | `0 -324` | **−0.2772** | 0.0858 |
| 3840×2160 (수정 후) | 2.0 | `0 -162` | **−0.1304** | 0.0825 |

- **글자 크기는 원래도 정상**이다 — 높이 비율이 해상도와 무관하게 같다(0.0858).
- **위치는 수정 전 4K에서 2배로 어긋났다.** 잉크 보정(+0.021, 아래 §3)을 빼면
  −0.2985 ≈ 2 × (−0.15) — conform 배수와 정확히 일치.
- **수정 후 4K가 1080p와 0.17%(프레임 높이) 안에서 일치**. 캡처 1px = 0.33%이므로
  측정 잡음 수준이다. 허용 오차 ±1.5% 대비 충분하다.

### 기본 설정에서 자막이 사라졌다

기본 y(`-420/1080 = -0.3889`)로 4K에 내보내면 수정 전 엔진은 Position `0 -840`을 썼고,
conform 2.0이 곱해져 **−1680px** → 프레임 절반(1080px)을 넘어 **화면 밖**이 된다.
뷰어 캡처에 자막이 아예 없는 것으로 확인했다. 1080p는 conform이 1.0이라 우연히 맞았을 뿐이다.

사용자 테스트 프로젝트 9개 중 **4개가 해당**한다 — 3840×2160 2개, 3840×1920 2개.

## 2. 확정된 좌표 모델

`basic`/`custom`/`custom123`의 `Position`은 **템플릿 씬(1920×1080) 좌표**이고,
FCP가 씬을 프로젝트에 conform(fit)한다.

```
conform  = min(proj_w / 1920, proj_h / 1080)      # basic/custom 계열
Position = frac × proj_h / conform                 # 씬 좌표로 환산해서 쓴다
렌더 위치 = Position × conform = frac × proj_h      # → 요청한 상대 위치와 일치
```

`subtitle` 템플릿(FCP 12.3 Subtitle.moti)은 씬이 3840×2160이고 정규화 리그 슬라이더를
쓰며, **이미 conform으로 나누고 있었다** — 이번 수정은 두 분기를 같은 모델로 통일한 것이다.

16:9에서는 `frac × proj_h / conform`이 언제나 `frac × 1080`이 된다(씬 높이).

## 3. 잉크 보정 — 측정의 계통 오차 (버그 아님)

측정한 y중심은 **글자 잉크 상자**의 중심이고, FCP가 Position에 맞추는 것은
**레이아웃 상자**다. `Xygq`(대문자+디센더)에서 그 차이는 **+0.021 프레임 높이**로 나왔다
(1080p: 요청 −0.150 → 측정 −0.1287). 글자 구성에 따라 달라진다 — `PROBE`(대문자만)는
+0.031이었다. 프리뷰와 비교할 때 이 값을 감안해야 한다.

## 4. 하네스를 만들며 실측으로 잡은 함정

1. **기준선을 흰색으로 그리면 안 된다** — 측정이 FCP 브라우저 썸네일을 기준선으로
   오인했다. FCP UI에 없는 **마젠타**를 쓴다.
2. **선 두께는 해상도 비례여야 한다** — 1px 선이 4K 뷰어 28% 축소에서 리샘플링에
   통째로 사라졌다. 프레임 높이의 0.4%로 그린다.
3. **한 클립에 타이틀 2개 이상이면 FCP 내부 임포터가 거부한다**(레인을 나눠도 동일,
   "드래그한 XML을 가져올 수 없습니다"). 측정점 하나당 프로젝트 하나로 만든다.
4. **같은 미디어 파일을 다른 asset uid로 다시 임포트하면 거부된다.** 이미 들어온
   uid를 재사용한다.

## 5. 남은 항목

- **프리뷰 쪽**: 화면비를 16:9/9:16 두 가지로만 가정한다(`inputIsPortrait` 1비트).
  3840×1920(2:1) 프로젝트는 프리뷰 레터박스와 배율이 둘 다 틀린다 — 실제 해상도를 써야 한다.
- **`subtitle` 스타일 실측 미완** — 이번엔 앱 기본 경로(`custom123`)만 쟀다.
  FCP 12.3+에서 자막 롤 토글을 켜면 그 분기를 타므로 같은 방식으로 재야 한다.
- **2줄 앵커** — `subtitle` 프리셋은 하단 정렬, `custom`은 중앙. 프리뷰는 항상 중앙이라
  2줄에서 자라는 방향이 다르다. 미측정.
