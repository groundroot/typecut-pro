# 스파인 직속 `<clip>` 누락 + 대본 첨부 (v0.13.47)

## 1. "타임라인에 분석할 오디오 클립이 없습니다" — 단일 타임라인인데 막혔다

### 증상

테스터 로그 `260821_시민의날축사` (v0.13.4, FCP 12.3, XML v1.14):

```
XML: v1.14, 전체 asset-clip 0 / sync-clip 0 / mc-clip 0 / ref-clip 0
프로젝트 스파인 직속: clip 4, transition 3
오류: 타임라인에 분석할 오디오 클립이 없습니다
[scan] 스파인 직속 7개(오디오 0) — 분석 대상(오디오) 0 / 통과 7
```

멀티캠도 컴파운드도 아닌 **평범한 단일 카메라 타임라인**이었다.

### 원인

`timeline_scan.py`의 `AUDIO_TAGS = ("asset-clip", "sync-clip")`. 스파인 직속에서
오디오로 인정하는 태그가 이 둘뿐이었고, 코드 주석에 그 가정이 명시돼 있었다 —
*"스파인 직속은 asset-clip/sync-clip만이라 AUDIO_TAGS 유지"*.

그 가정이 틀렸다. FCP는 비디오/오디오가 한 `<asset-clip>`으로 접히지 않을 때
스파인에도 일반 `<clip>` 컨테이너를 쓴다. 이 프로젝트는 전부 그 형태였다
(문서 전체 asset-clip **0개**).

로컬 프로젝트에서 실제 구조를 확인했다 (`2025 리멤버 편집 메인(2)`):

```xml
<clip offset="…" name="IMG_5245" duration="…" format="r59">
  <adjust-volume amount="-96dB"/>
  <video ref="r60" offset="0s" duration="14s">
    <audio ref="r60" lane="-1" offset="0s" duration="14s"
           role="dialogue.dialogue-1" srcCh="1, 2"/>
  </video>
</clip>
```

오디오는 `<video>` **안에** 중첩돼 있다. 스파인 직속 태그만 보면 영원히 안 보인다.

### 고친 것

`clip_audio_sources(el)` — `<clip>` 안에서 **실제로 소리를 내는** 요소를 모은다.
꺼진 컴포넌트(`enabled="0"`)와 음소거(`adjust-volume -96dB`, `srcEnable="video"`)는
제외한다. 스파인 루프는:

- 소스가 **하나** → 그 소스로 분석
- 소스가 **둘 이상** → 어느 쪽 말인지 결정 불가 → 통째 보존 + 사유 표시
  (컨테이너 `ContainerAmbiguous` 규칙과 같은 철학)
- 소스가 **없음**(b롤·음소거) → 지금까지처럼 조용히 통과

소스 인점(TC)도 클립이 아니라 **그 오디오 요소의 `start`** 를 먼저 본다 —
오디오가 밀린 클립에서 클립 start를 쓰면 자막이 통째로 어긋난다.

### 덤으로 잡힌 것 — 음소거 b롤의 유령 자막

같은 헬퍼를 연결 `<clip>` 경로에도 쓰게 되면서, **-96dB로 깔아 둔 b롤이 더는
분석되지 않는다.** 로컬 프로젝트 전수 비교에서 드러났다:

| 프로젝트 | 이전 오디오 항목 | 이후 |
|---|---|---|
| `111` | 213 | 212 |
| `2026 대영교회 홍보영상(3)` | 316 | 304 |

줄어든 13개 전부 `adjust-volume -96dB`였다. 소리가 없는 구간을 STT에 넣으면
환청 자막이 붙는다 — 그동안 붙고 있었다.

나머지 로컬 프로젝트 전부는 **결과 동일**(회귀 없음).

### 남은 것

테스터의 원본 `.fcpxml`은 받지 못했다. 구조는 로그(`clip 4 / asset-clip 0`)와
동일 형태의 로컬 실파일로 재현했지만, **그 파일 자체로는 확인하지 못했다.**

## 2. 대본 첨부 — 용어를 하나씩 등록하는 대신 원고를 통째로

### 건의 (사용자, 2026-08-24)

> 텍스트 기반편집을 최초에 분석할때 거기에 참고용으로 써지면 훨씬 좋을 것 같습니다.
> 전문용어 등 고유명사? 교정으로 하기보단, 작성해논 대본을 첨부해서 같이 학습만
> 가능하게하면 훨씬 정확해질거같아 건의드려봅니다!

### 만든 것

`--script <파일>` (앱: 분석 탭 → **대본 첨부…**). `.txt` / `.md` / `.srt` / `.vtt`.
자막 번호·타임코드와 마크다운 기호는 걷어내고 읽는다.

대본은 **두 지점**에서 쓰인다.

**① 인식 전 — ASR 힌트**
대본에서 고유명사·전문용어 후보를 뽑아 기존 용어 사전과 같은 통로
(ASR system_prompt)로 넣는다. 후보 기준:

- 직함이 뒤따르거나 붙는 말 (`정예린` 시장님, `홍길동 의원`)
- 약어·숫자 섞인 말 (`LUT`, `GRDP`, `4K`)
- 3음절 이상 + 3회 이상 반복 + **어미·조사로 끝나지 않는** 말

마지막 조건이 없으면 `그리고`·`합니다`·`때문에`가 용어 목록에 섞이고, 모델이
그 목록을 되뱉는다. 영문 대본에선 `is`/`the`/`on`이 통째로 딸려 왔다 (실측:
4줄짜리 영문 대본에서 21개 → 2개).

**② 인식 후 — 철자 맞추기**
대본 어휘로 발음 사전을 만들어, **소리가 완전히 같은데 철자만 다른** 단어를
대본 철자로 되돌린다.

```
종노구에서 → 종로구에서      실라호텔 → 신라호텔      구지 → 굳이
```

손대지 않는 선을 넷 뒀다:

1. **1음절은 절대** — `이/의`, `되/돼` 동음이의가 너무 흔하다
2. **대본 안에서 후보가 갈리면 안 고른다** — 대본에 `같이`와 `가치`가 둘 다 있으면 포기
3. **STT가 그 철자를 다른 데서 이미 정확히 썼으면 안 고친다** — 못 쓰는 게 아니라는 뜻
4. **소리가 완전히 같을 때만** — 비슷한 소리는 건드리지 않는다
   (`difflib` 유사도 0.85로 하던 옛 `retranscribe` 경로와 다른 점)

조사는 양쪽 다 떼어 보고 어간으로 맞춘다 (`신라호텔에서`(대본) ↔ `실라호텔`(STT)).
임의의 1~2글자가 아니라 **조사 목록**으로만 뗀다 — `있습니다`에서 2글자를 떼면
`있습니`라는 쓰레기 어간이 생겨 오탐이 된다.

### 발음 규칙 하나 추가 — ㄹ의 비음화

`phonetic.py`에 ㅁ/ㅇ 종성 뒤 ㄹ → ㄴ (`종로`=[종노], `강릉`=[강능]), 그리고
상호 비음화 ㄱ/ㅂ + ㄹ (`독립`=[동닙], `협력`=[혐녁])을 넣었다. 지명·인명이
대본 첨부의 주 대상인데 이게 없으면 `종로`를 못 잡는다.

과병합 위험은 없다 — 둘 다 실제로 같은 소리다. 기존 AI 문맥 교정의
'같은 소리 묶기' 테스트 전부 통과.

### 캐시

분석 캐시 지문에 대본 해시를 넣었다 — 대본을 바꾸면 재분석된다.
`hash()`가 아니라 SHA-1을 쓴다(파이썬 내장 `hash()`는 실행마다 값이 달라져
캐시가 영영 안 맞는다).

### 대본은 영속하지 않는다

대본은 그 영상의 원고다. 입력이 바뀌거나 비면 함께 비운다 — 안 그러면 다음
프로젝트에 남의 원고가 붙는다.

### 안 한 것

- **느슨한 모음 매칭** (`정예린`↔`정에린`, ㅖ/ㅔ). 표준 발음으론 다른 소리다.
  실제 오인식 빈도를 재고 나서 판단한다.
- **문장 단위 정렬**. 대본과 발화를 문장으로 맞추면 커버리지가 크게 늘지만,
  즉흥 발언·순서 바뀜에서 조용히 틀린다. 어절 발음 일치만으로 시작한다.
