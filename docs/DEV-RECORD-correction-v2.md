## 1. 한국어 발음 정규화 (`silence_cutter/phonetic.py`)

STT 오인식의 큰 몫이 **발음은 같은데 표기가 다른 것**이다. 자모로 풀고
표기 흔들림을 만드는 음운 규칙만 적용해 한 키로 묶는다.

적용 규칙: 격음·경음 → 평음 / 7종성 중화 / 유음화(ㄹ+ㄴ→ㄹㄹ) / 비음화 /
구개음화(ㄷ·ㅌ + ㅣ → ㅈ) / 연음 / 모음 통합(ㅐ=ㅔ, ㅚ=ㅙ=ㅞ, ㅢ=ㅣ).

| 묶여야 하는 것 | 결과 | 갈라져야 하는 것 | 결과 |
|---|---|---|---|
| 솔님이 / 솔림이 | 같음 | 솔님이 / 설임이 | 다름 |
| 신라 / 실라 | 같음 | 올라프 / 올리프 | 다름 |
| 국물 / 궁물 | 같음 | 가다 / 거다 | 다름 |
| 같이 / 가치 | 같음 | 쓸모없는 / 쓸모있는 | 다름 |
| 낮 / 낫 | 같음 | | |

### 여기서 내린 제품 결정 — 발음만으로 자동 교정하지 않는다

"같이"/"가치", "낮"/"낫"처럼 **소리가 같아도 다른 낱말인 짝이 흔하다.**
한 대본에 두 표기가 다 나온다고 해서 한쪽이 틀린 게 아니다. 그래서 발음
그룹은 **사람이 확정한 교정의 확장**으로만 쓴다 — 사용자가 "이건 같은 말"
이라고 판단한 뒤에야 나머지 자리를 일괄 수정할 수 있다.

효과: 사전에 `솔예나(솔님이 아님)` 하나만 등록해도, STT가 흘린 `솔림이`를
같은 발음으로 찾아 함께 고칠 수 있다. `설임이`는 안 딸려온다.

## 2. 수사 → 숫자 표기 (`silence_cutter/numfmt.py`)

"십만 원" → "10만원", "사점사 퍼센트" → "4.4%". 모델에 맡기면 문장마다
결과가 흔들려서 **로직으로 고정**했다.

**오변환이 미변환보다 나쁘다** — 자막에 "10원래"가 박히면 안 고치느니만
못하다. 두 겹으로 잠근다:

1. **단위가 붙은 것만** 바꾼다. 맨 수사는 손대지 않는다.
2. 앞이 한글로 이어지면 단어 중간이므로 건너뛴다("선생님이").
3. 단위를 두 갈래로 나눠 뒤를 다르게 잠근다:
   - **자립 단위**(퍼센트·프로·달러·개월·시간·킬로…) — 딴 낱말과 안 겹치므로
     뒤에 무엇이 와도 좋다. "퍼센트래요" ✓
   - **모호 단위**(원·도·분·대·장·회…) — 한 글자라 딴 낱말의 첫 글자이기 쉽다.
     조사·문장부호·끝만 허용한다. "원래"·"도서관" ✗

실발화 표본 20종 측정 (`tests/test_numfmt.py`):

| 바뀌어야 하는 것 (10/10) | 안 바뀌어야 하는 것 (10/10) |
|---|---|
| 삼십만 원씩 → 30만원씩 | 십 원래 그렇다 |
| 사점오 퍼센트래요 → 4.5%래요 | 선생님이 원하는 |
| 사천만 원인데 → 4000만원인데 | 도서관에 갔다 |
| 일억 이천만 원짜리 → 1억 2000만원짜리 | 원인을 찾자 |
| 십 프로 → 10% | 만나서 반갑다 |

### 적용 지점 — 단어 단계여야 한다

`engine.py`의 단어 확정 직후(전사 후, 화자 런 전). 자막 텍스트에만 적용하면
**대본 편집기는 한글, 자막은 숫자**로 갈린다. 단어를 합칠 때 시각은
첫 단어 시작 ~ 마지막 단어 끝으로 잡아 재생 위치를 지킨다.

### 실콘텐츠 측정 — 요즘 STT에선 잘 안 걸린다

테스트 영상 3편(입덕 부정기 / 1억 언더 신차 / 절약이 습관이 된 사람들)에서
**단어 병합이 한 번도 안 일어났다.** Qwen이 이미 숫자로 적기 때문이다 —
"폴스타 3", "780kg", "6000원", "100만원", "10킬로", "2순위". 그리고 **이미
숫자인 것을 망가뜨리지도 않았다**(멱등).

즉 이 기능의 값어치는 STT가 한글로 풀어 쓰는 경우에 한정된다. 측정 근거는
단위 테스트 수준이고, **실영상에서 발화 금액이 한글로 나오는 빈도는 아직
못 쟀다** — 이 기능이 실제로 얼마나 일하는지 숫자로 말할 수 없다.

## 3. 승인 시트 (앱 `CorrectionReviewView.swift`)

"제안을 보고 승인/거부"에서 **확정할 수 있는 절차**로:

- **미리 듣기** — 교정 자리를 앞뒤 0.7초 여유를 두고 재생. 단어 하나(0.3초)만
  들려주면 무슨 말인지 못 알아들어 확정에 못 쓴다. 다중 소스라 후보마다
  자기 항목의 추출 WAV 경로를 싣는다.
- **선택지** — 제안 + 대본의 다른 표기를 칩으로. 타이핑 없이 고른다.
- **전체 수정** — 같은 발음 자리들을 조용히 적용하지 않고 **항목으로 펼친 뒤**
  함께 승인받는다(개별로 되돌릴 수 있게).

진입점: 설정의 **AI 문맥 교정** 토글. 엔진 `--correct-llm`은 있었으나 앱에서
닿지 않던 상태였다(2026-08-11에 뺐던 것은 검토 절차가 없는 중복 기능이었다).
`--correct-llm`은 `--correct-context` 안에서만 동작하므로 함께 넘긴다.

## 4. 게이트 왕복 실증 (앱 없이 계약만 검증)

`입덕 부정기.fcpxml` + 사전 `팀장님(팀자님 아님)`으로 엔진을 돌리고,
앱 대신 손으로 `approved.json`을 회신했다.

- `proposals.json`: 후보 1건 `팀자님 → 팀장님` [term] `79.18~79.58s`,
  `audio` 경로 있음, `candidates=['팀장님']`, `same_sound=0`(그 자리 하나뿐).
- 새 필드 5종(`start`·`end`·`audio`·`candidates`·`same_sound`) **누락 없음**.
- 승인 회신 후 출력 자막에서 **`팀자님`이 사라지고 `팀장님`만 남았다.**

앱 쪽은 이 JSON을 디코딩하는 계약을 `CorrectionDecodeTests`로 잠갔다 —
이 디코딩이 깨지면 시트가 **조용히 안 뜨고** 분석은 그대로 진행돼 실패가
눈에 안 띈다.

## 남은 것

- 실영상에서 **한글 금액 발화 빈도** 미측정 — 이 기능이 실제로 얼마나 일하는지
  아직 숫자로 말할 수 없다.
- 발음 그룹의 **재현율** 미측정 — STT 표기 흔들림 중 몇 %를 묶는지 모른다.
  라벨링된 오인식 쌍이 있어야 잴 수 있다.
- 교정 시트는 여전히 **분석 중**에 뜬다. 분석이 끝난 뒤 편집 단에서 다시
  열어 재실행하는 경로는 없다.
